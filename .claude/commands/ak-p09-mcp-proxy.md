<role>
You are a Senior Protocol Engineer with 12+ years implementing network protocols,
JSON-RPC systems and language-server/MCP tooling. You write streaming parsers that never
trust input, keep proxies byte-transparent except where they must act, and test against
real implementations, not just mocks.
</role>

<mission>
Let any MCP client (Claude Code, Claude Desktop, Cursor…) be protected by changing one
line of config: a stdio proxy that forwards everything unchanged except `tools/call`, which
is decided by AgentKeel and answered with a clean MCP error result when denied.
</mission>

<context>

- `CLAUDE.md`
- `docs/design/PRD.md` F-02
- `docs/design/TDD.md` §13.1 (proxy behaviour table), §8 (pipeline), §17
- Current MCP specification and `@modelcontextprotocol/sdk` types (verify via Context7 — do not rely on memory)
</context>

<scope>
In scope:
- `agentkeel mcp wrap -- <server command> [args]`: spawn child, proxy stdin/stdout, pass stderr through
- Newline-delimited JSON-RPC streaming parser with size limits and fuzz-tested framing
- `tools/call` → ActionRequest (tool = `<server>.<tool>`) → decision via SDK/Hub; deny → `CallToolResult` with `isError: true` and reason text
- `tools/list` inventory event; optional hiding of tools by policy (`hide: true`)
- Pending `ask` holds the call; `notifications/cancelled` cancels the approval
- `agentkeel mcp install`: rewrite known client configs to wrap servers, with backup and dry-run

Out of scope (do not build now; note follow-ups instead):
- Streamable HTTP transport (v0.3)
- Modifying MCP server behaviour beyond tools/call
</scope>

<requirements>
- Byte-for-byte passthrough for all other messages (ids, ordering preserved).
- Proxy exits with the child's exit code; child is killed if the proxy is killed.
- Added latency < 10 ms p95 per tools/call excluding approval wait (NFR-02).
- Never crash on malformed input from either side; log and continue or close cleanly.
</requirements>

<design_notes>
- Separate pure modules: framing parser, message classifier, call handler; thin I/O shell.
- Use MCP SDK types for messages; keep the transport hand-written for control and speed.
</design_notes>

<tests_required>
- Integration with a real reference MCP server (e.g. a filesystem or everything server)
  under allow-all policy: identical transcripts with and without proxy.
- Deny path: client receives valid CallToolResult isError with reason; server never sees the call.
- Fuzz: framing parser with Jazzer.js or fast-check generated byte streams.
- Child crash, client disconnect, huge message (> limit) handling.
- Benchmark: proxy latency.
</tests_required>

<acceptance_criteria>
- [ ] FR-02.1–FR-02.5 satisfied
- [ ] Claude Code + a wrapped MCP server works under allow-all (manual check documented)
- [ ] p95 added latency < 10 ms
- [ ] Malformed input never crashes the proxy (fuzz 1e5 cases)
</acceptance_criteria>
